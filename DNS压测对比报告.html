复测结论：本次优化作用在回源路径，热缓存路径无法通过本轮压测判定。

三、为什么热路径测不出来

复测做了三重扩展验证，吞吐始终锁死在 54k：

单进程 1 线程
54,480
4 进程并行（合计）
54,443
节点本机实测
94,000
4 个独立进程吞吐相加仍为 54k，说明限制点在单进程之外；节点本机能力约为该值的 1.7 倍
排除项观测值结论
压测端 loopback 能力93,791 – 102,860 QPS软件层无瓶颈
压测端 CPU @ 54kuser 24.1% / sys 32.1% / softirq 9.6% / idle 34.1%算力未打满
softnet / 网卡丢包0 / 0协议栈无丢包
网卡形态virtio_net，2 combined 队列，2 vCPU宿主机 pps 限额为常见成因
4 进程并行13,666 + 13,600 + 13,602 + 13,575 = 54,443非单进程限制
判定
54k = 压测路径上限，94k = 节点能力。本轮复测对"热路径是否提升"没有分辨力。节点实际能力高于本轮所有热缓存测量值，因此本报告不对热路径优化效果下结论。

综合判断：优化在回源路径上确实生效，黑盒数据能佐证方向，但精度不足以量化幅度。

六、容量模型确认

采纳命中率加权模型：

C_total = 1 / ( H / C_hit + (1-H) / C_miss )

H       = 热缓存命中率
C_hit   = 热缓存单节点吞吐（规划值 50,000）
C_miss  = 回源单节点吞吐（实测 1,049，按 800 规划）
命中率 H单节点吞吐适用业务
100%50,000理论值，不可达
99.5%22,000高热度业务（CDN、大站）
99.0%15,500典型 Web 业务
98.0%10,300长尾业务
95.0%5,250爬虫 / 监控类
90.0%2,700几乎不重复

补充：C_hit 取 50k 作为规划值是安全的——本轮证明单个普通 2 vCPU 客户端即可将节点压到 54k 且零丢包，节点实际仍有近一倍余量。但需同时注意：单客户端观测上限就是 54k，扩容判据不能依赖单机压测。

七、方法局限

#局限影响
1压测源为 2 vCPU / virtio 单机，热路径上限 54k无法验证 94k 区间的任何变化
2无服务端权限，无法 flush 缓存重放同一批域名冷测引入域名质量差异，不能严格 A/B
3全程黑盒，无 cache hit/miss、迭代耗时指标无法直接观测优化项的实际生效情况

优先级动作解决的问题
